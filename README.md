# cloak

## این پروژه چیه

یه ابزار کوچیکه که کمک می‌کنه اتصال HTTPS گوشیت (وقتی از یه VPN/پراکسی مثل v2rayNG استفاده می‌کنی) راحت‌تر از فیلترینگ رد بشه — بدون نیاز به روت کردن گوشی.

**یه نکته‌ی مهم و صادقانه:** من (کسی که این پروژه رو ساخته) برنامه‌نویسی یا شبکه بلد نیستم. این کل ماجرا از یه کنجکاوی شروع شد — می‌خواستم بفهمم فیلترشکن‌هایی که استفاده می‌کنم دقیقاً چطور کار می‌کنن. این پروژه، از اولین خط کدش تا آخرین ویژگیش، **صفر تا صد با هوش مصنوعی (Claude)** ساخته شده. من فقط سؤال پرسیدم، ایده دادم، و تست کردم؛ خودِ کد، معماری، و تصمیم‌های فنی همه از طریق گفتگو با AI شکل گرفت.

این رو می‌گم چون فکر می‌کنم شفافیت مهمه — اگه دنبال یه پروژه‌ی دست‌ساز از یه برنامه‌نویس باتجربه می‌گردی، این اون نیست. ولی اگه کنجکاوی مثل من داری و می‌خوای ببینی امروز با کمک AI چقدر میشه پیش رفت، شاید براش جالب باشه.

---

## اسمش چرا «cloak»‌ـه

اول اسم‌های اشتباهی مثل «spoof» رو امتحان کردیم، ولی وقتی دقیق‌تر بررسی کردیم فهمیدیم این ابزار واقعاً «جعل» (spoof) نمی‌کنه — چون spoof واقعی (جا زدن پکت جعلی روی همون اتصال واقعی) فقط با دسترسی روت ممکنه. کاری که این ابزار می‌کنه چیز دیگه‌ایه: اتصال واقعی رو **پنهان** می‌کنه پشت یه اتصال جعلیِ بی‌خطر که زودتر می‌میره. کلمه‌ی انگلیسیِ دقیق برای «پنهان کردن زیر یه پوشش» میشه **cloak** (مثل شنل‌نامرئی‌کننده) — پس اسم رو گذاشتیم رو همون چیزی که واقعاً هست، نه چیزی که نیست.

## چطور کار می‌کنه (به زبان ساده، بدون فرض دانش قبلی)

وقتی گوشیت می‌خواد به یه سایت وصل بشه، اولین پیامی که می‌فرسته یه چیزی شبیه «سلام، من می‌خوام با فلان‌سایت.com صحبت کنم» هست — این پیام رمزنگاری نشده، پس فیلترینگ می‌تونه بخونتش و اسم سایت رو ببینه و بلاکش کنه.

`cloak` این کارو می‌کنه:

1. یه پیامِ «سلام» **جعلی** می‌سازه که توش یه اسم سایتِ مجاز (مثلاً یه سایت تست سرعت) نوشته.
2. این پیام جعلی رو با یه ترفند فنی (کم کردن «عمر» پکت) می‌فرسته، طوری که این پیام **قبل از رسیدن به مقصد واقعی** توی مسیر گم/نابود بشه — ولی سیستم فیلترینگ (که معمولاً نزدیک‌تره) قبلش می‌بینتش و فکر می‌کنه اتصال به یه سایت مجازه.
3. بلافاصله بعدش، پیامِ **واقعی** (با اسم سایت واقعی) رو می‌فرسته که این یکی درست به مقصد می‌رسه.

نتیجه: فیلترینگ فکر می‌کنه داری به یه سایت بی‌خطر وصل میشی، درحالی‌که اتصال واقعیت به مقصد اصلیش رسیده.

**صادقانه بگم:** این معادلِ کاملِ تکنیک‌های حرفه‌ایِ روت‌محور نیست، ولی قوی‌ترین نسخه‌ایه که بدون روت روی گوشی ممکنه.

---

## چیزایی که `cloak` بلده

- کار بدون روت
- امتحان چند سرور مقصد هم‌زمان (هرکدوم زودتر جواب داد، همونو استفاده می‌کنه)
- یادگیری خودکار از تجربه (یادش می‌مونه کدوم تنظیمات جواب داده)
- پشتیبانی از IPv4 و IPv6
- همه‌چیز از یه فایل تنظیمات ساده کنترل میشه، نیازی به دستور پیچیده نیست

راهنمای کامل تنظیمات و سناریوهای مختلف رو توی [`cloak-guide.md`](cloak-guide.md) بخون.

## ابزار دوم: `cloakscan` — پیدا کردنِ IP و SNIِ تازه

### این ابزار چیه و چرا لازمه

`cloak` خودش IP جدید کشف نمی‌کنه — تو یه لیست IP و SNI بهش میدی، خودش فقط بینشون انتخاب می‌کنه و یاد می‌گیره کدوم بهتره. ولی IPهای تمیزِ کلادفلر **مدام عوض میشن** (وقتی یه IP لو بره یا پرترافیک بشه، بلاک میشه). `cloakscan` یه ابزارِ جداست که کارش دقیقاً همینه: یه رنجِ بزرگِ IP رو می‌گیره، توش می‌گرده، و IPها/دامنه‌هایی که **الان واقعاً کار می‌کنن** رو پیدا می‌کنه — و خودکار توی `cloak.conf` می‌نویسدشون.

### چطور کار می‌کنه (به زبان ساده)

1. یه رنجِ بزرگِ IP (مثلاً همه‌ی IPهای کلادفلر) رو می‌گیره.
2. به‌جای چک‌کردنِ **همه‌شون** (که میلیون‌هان و عمراً زمانش برسه)، یه تعداد **نمونه‌ی رندوم** ازش انتخاب می‌کنه.
3. برای هر IPِ نمونه، یه دامنه‌ی کاندید (از لیستی که خودت میدی) رو باهاش تست می‌کنه — یعنی واقعاً بهش وصل میشه و می‌بینه جواب درستی میده یا نه.
4. هرکدوم که جواب داد، به‌عنوان یه ترکیبِ «کارآمد» ثبت میشه.
5. در آخر، این ترکیب‌های کارآمد رو **خودکار** توی `cloak.conf` (توی `connect_list` و `sni_list`) اضافه می‌کنه — بدون اینکه تو دستی کپی‌پیست کنی.
6. یه قابلیتِ اضافه هم داره: قبل از اضافه‌کردنِ چیزِ جدید، اول IPهای **قدیمیِ** توی `cloak.conf` رو دوباره تست می‌کنه و اگه یکی دیگه کار نمی‌کرد، حذفش می‌کنه — یعنی `cloak.conf` همیشه «تازه» می‌مونه، نه فقط بزرگ‌تر.

### نصب و اجرا (دقیقاً مثل `cloak`)

```bash
pkg install clang    # اگه قبلاً نصب نکردی
gcc -O2 -Wall -o cloakscan cloakscan.c -lpthread
./cloakscan           # اولین اجرا: فایل cloakscan.conf رو می‌سازه
```

⚠️ **نکته‌ی مهم:** `cloakscan.c` رو باید **کنارِ `cloak.c`** توی همون پوشه بذاری، چون به‌صورت پیش‌فرض دنبال `cloak.conf` توی همون پوشه می‌گرده تا بهش آپدیت بده.

فایل `cloakscan.conf` رو باز کن (`nano cloakscan.conf`)، تنظیماتو چک کن (توضیح کامل زیرشه)، ذخیره کن، دوباره بزن:

```bash
./cloakscan
```

### تنظیمات `cloakscan.conf` — توضیح هر خط

```ini
# رنج‌های IP که توش می‌گرده (IPv4 و IPv6 با هم قابل ترکیبن)
ranges = 104.16.0.0/13, 104.24.0.0/14, 172.64.0.0/13, 2606:4700::/32
```
این‌ها رنج‌های رسمیِ کلادفلرن (از قبل توی کانفیگ پیش‌فرض هستن). اگه یه روز کار نکردن، لیستِ به‌روزش همیشه اینجاست: `https://www.cloudflare.com/ips/`

```ini
# دامنه‌های کاندید که تست میشن
sni_list = www.hcaptcha.com, www.speedtest.net, www.bing.com, www.cloudflare.com
```
هر دامنه‌ای که فکر می‌کنی خودش بلاک نیست، اینجا اضافه کن — بیشتر باشه، احتمالِ پیدا کردنِ ترکیبِ کارآمد بیشتره.

```ini
port = 443
samples_per_range = 40      # چند تا IP رندوم از هر رنج تست بشه
concurrency = 20             # چند تا تست هم‌زمان (بیشتر = سریع‌تر ولی سنگین‌تر)
timeout_ms = 2000            # هر تست چقدر صبر کنه قبل از رد شدن
```

```ini
output = cloakscan_results.txt
```
یه فایلِ سابقه که همیشه نتایجِ خام رو نگه می‌داره (حتی اگه `auto_update` رو خاموش کنی).

```ini
auto_update = true           # نتایج رو خودکار توی cloak.conf بنویسه
cloak_conf_path = cloak.conf # آدرسِ فایلِ اصلی
max_servers_write = 8        # سقفِ تعدادِ IP توی connect_list
max_snis_write = 12          # سقفِ تعدادِ SNI توی sni_list
prune_dead_entries = true    # قبل از اضافه‌کردن، قدیمیایی که دیگه کار نمی‌کنن رو پاک کنه
```

پیش‌فرض همه‌شون طوریه که فقط `./cloakscan` بزنی و همه‌چیز خودکار انجام بشه — نیازی نیست این‌ها رو عوض کنی مگه بخوای رفتار خاصی داشته باشه.

### یه اجرای نمونه چه شکلیه

```
$ ./cloakscan
cloakscan: 4 range(s), 40 samples each, 4 SNI candidate(s), concurrency=20
[FOUND    1/160 ] 104.18.29.103 -> www.cloudflare.com
[FOUND    2/160 ] 104.20.40.45 -> www.cloudflare.com
...
[auto_update] wrote 8 server(s) and 6 SNI(s) into cloak.conf
done: 40/160 probes succeeded. Results in cloakscan_results.txt
```

بعدش کافیه `cloak` رو (دوباره) اجرا کنی تا از تنظیماتِ تازه استفاده کنه.

### چند وقت یه‌بار باید اجراش کنم؟

هیچ قانونِ ثابتی نیست، ولی یه‌بار در هفته منطقیه — اگه یهو حس کردی `cloak` دیگه به هیچ سروری وصل نمیشه، همون لحظه هم `cloakscan` رو بزن.

## محدودیت‌ها (صادقانه)

- این جایگزینِ کاملِ اسپوفِ سطح‌روت نیست.
- اثربخشیش به شرایط شبکه‌ی هر شخص بستگی داره — ممکنه برای یکی عالی کار کنه و برای یکی دیگه نه.
- نتیجه‌ی `cloakscan` فقط یه «عکسِ لحظه‌ای»ه — یه IP که الان جواب میده، ممکنه فردا بلاک بشه.
- این پروژه رو یه فرد کنجکاو با کمک AI ساخته، نه یه تیم امنیتی حرفه‌ای — ازش با همین دید استفاده کن.
